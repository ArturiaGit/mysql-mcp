## 1. 验证原则

页面实现或相关交互变更后，按影响范围检查；本次仅写文档，不启动视觉测试。验证工具可使用项目实际可用的浏览器预览或后续选定的测试工具，不绑定特定代理环境，也不照搬其他项目禁止某类测试工具的规则。

视觉、交互和后端安全是不同证据：截图证明展示，不证明 SQL 未执行；安全行为还需[测试矩阵](./CODE_REVIEW.md)。所有数据使用虚构资料，避免截图包含密码、登录码、真实 SQL 或业务结果。

## 3. 检查流程

1. 记录源码版本或文件状态、系统、浏览器/客户端版本、测试数据来源。
2. 确认测试环境为模拟数据；如涉及真实操作，先取得额外授权。
3. 桌面建议 1440×900，窄屏建议 375×812，增加 200% 缩放与键盘流程；实际执行的视口单独记载。
4. 检查布局溢出、长 SQL 局部滚动、对比度、焦点、错误可读性、按钮防误点；主题仅覆盖实际实现的主题。
5. 对批准、拒绝、过期、失效、未知结果留状态证据；不把缺失场景标通过。
6. 有缺陷先记录明确复现和影响，修复后重测对应范围。

涉及全局样式覆盖全部已实现页面；表单变更重点 UI-03/04/05；审批逻辑变更覆盖 UI-07 至 UI-10 及 UI-12。独立客户端窗口需单独实测，本地网页预览不能替代。
