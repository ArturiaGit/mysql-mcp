# 阶段实施路线图

> 状态：未来实施路线草案，软件尚未开始实现。当前仅交付规范文档，不把历史软件提案视为执行授权。

## 1. 文档基线

本次建立根目录 docs 的 15 份规范，以[需求基线](./REQUIREMENTS.md)区分已确认、事实、提案及待验证项。完成文档不等于完成任何软件阶段；具体文档检查结果由本次交付说明报告。

## 2. 软件阶段（全部未完成）

### Phase 1：工具链及可行性

进入条件：软件实施获授权，复核工作区变更。

- [ ] 建立 Node.js/TypeScript 工程和锁文件。
- [ ] 验证 Windows 凭据模块，虚构凭据 CRUD/重启后清理。
- [ ] 验证 MCP SDK 与 SQL 解析器/驱动的关键行为。
- [ ] 固定运行版本、资源上限、持久化策略与语法矩阵。

退出条件：有可复现工具链与模拟检查；安全关键候选依赖可用，不能以明文后备绕过失败。

### Phase 2：连接管理及认证

- [ ] 回环单实例服务、本地认证和 CSRF/Host/Origin 防护。
- [ ] 连接 CRUD、稳定 ID、凭据引用、原子配置与补偿清理。
- [ ] 页面状态、编辑密码语义和连接测试模拟。

退出条件：未认证请求不可更改资料，错误不泄密；执行相关资料版本规则明确。

### Phase 3：受限读取及 MCP

- [ ] 七个拟定工具的协议骨架，读取与变更入口分离。
- [ ] 元数据/SELECT 策略、目标隔离、精度和结果限制。
- [ ] stdio 协议测试，错误与日志脱敏。

退出条件：模拟读取通过，副作用/多语句/跨目标负面测试通过；尚不宣称真实数据库可用。

### Phase 4：写入审批与故障语义

- [ ] 单次请求绑定和状态机，本地人工审批。
- [ ] 原生 elicitation 桥接及网页后备，拒绝不改道。
- [ ] 并发去重、到期、版本失效、状态日志及重启 UNKNOWN。
- [ ] 常见 DML/DDL 策略，写入不自动重试。

退出条件：确认前和拒绝/失效情况下无派发；重复批准无第二次派发；不承诺万能回滚或恰好一次。

### Phase 5：三个客户端与界面

- [ ] 记录 PI-Desktop、Codex 桌面、WorkBuddy 桌面实际版本。
- [ ] 逐端验证接入、工具发现及无副作用确认探针。
- [ ] 不可靠原生确认采用网页后备并验证。
- [ ] 执行相关 UI/可访问性检查并登记证据。

退出条件：兼容矩阵逐项记录通过或未验收；不能用一个客户端结果代表三端。

### Phase 6：真实隔离库验收与交付

进入条件：DBA 提供测试范围，用户本地输入凭据并另行授权；写/DDL 仍逐次确认。

- [ ] 验证 MySQL 版本、权限、连接、列库列表和结构。
- [ ] 在隔离库验证读取、DML/DDL 的允许及拒绝路径。
- [ ] 完善启动、升级、限制说明和实际测试报告。
- [ ] 用户确定首个业务查询，按授权范围验收。

退出条件：真实检查有证据，业务库未被自动修改；剩余限制公开，发布另行授权。

## 3. 未决项与阻塞处理

客户端版本/能力、数据库可用性、凭据模块、SQL 方言、TLS 和业务场景见需求 Q01–Q08。缺少实机或隔离库可以继续模拟开发，但不得把未执行验收标通过。安全关键能力失败时停止对应写功能，不以降低确认要求推进。

## 4. 进度治理

任务完成需要实现与相关验证证据，不以“代码已写”作为唯一标准。规划记录见[任务台账](./plans/README.md)；范围变更同步需求和契约，不在路线图中偷偷扩展功能。发布候选版本待可运行基线形成后决定，当前不设虚假版本进度。
