# 前端 UI 与交互规范

> 状态：拟定设计；页面尚未实现，无视觉基线。**前端界面全量由 Antigravity 专职设计、编写与维护（收敛于 `mysql-mcp/web/`）**，详见[全栈分工规范](./FULLSTACK_DIVISION_SPECIFICATION.md)。功能要求来自[需求](./REQUIREMENTS.md)，接口见[协议](./API_AND_PROTOCOLS.md)。

## 1. 信息结构

| 拟定页面 | 主要内容 |
|---|---|
| /login | 本地登录码、说明、失效/限速反馈 |
| /connections | 连接列表、添加、编辑、测试、删除 |
| /changes | 待审批与执行状态列表 |
| /changes/:request_id | 准确目标、完整 SQL、风险和人工审批 |

不扩展通用 SQL 编辑器、业务报表或数据库运维控制台。连接名称与地址同时展示，避免同名误操作；默认数据库标识不等于本次操作目标。

## 2. 连接表单

字段：名称、地址、端口、用户名、密码、可选默认数据库。端口只接受 1–65535 整数；地址不得是含密码 URL。错误贴近字段并提供可访问说明。

- 新增密码由用户输入；不填入历史 root 或记忆中的未验证地址。
- 已保存密码不回显，不用假的星号字符串冒充真实值。编辑提示“留空保持原密码”，提交时省略 password。
- “测试连接”和“保存连接”是不同动作，测试失败不显示保存成功；测试草稿不持久化。
- 保存、测试期间防重复提交，失败保留非敏感输入；关闭/提交后尽快清理密码内存，不写 Web Storage。
- 删除明确写“删除本地连接资料及凭据，不删除数据库”；执行中的连接不得删除。

## 3. 审批交互（必须满足的目标行为）

展示连接名称、地址、用户名、目标数据库、请求 ID、来源客户端、完整准确 SQL、原因、过期时间与风险。SQL 按文本安全渲染，不使用未经净化的 HTML。

批准按钮写“批准并执行本次 SQL”，与拒绝/取消明确区分。默认焦点不能落在批准按钮，不提供“始终允许”；倒计时仅提示，最终期限由服务端判断。SQL 只读，不在审批界面编辑；目标或内容变化必须重新创建请求。

无 WHERE 更新/删除、DROP、TRUNCATE、覆盖式插入和 DDL 隐式提交应有明确警告。不要编造影响行数，也不能把一次预览说成最终影响范围。既有触发器与外键可能产生间接效果。

网页与原生确认采用同一内容要求；原生无法完整展示或可靠逐次询问时使用网页后备。拒绝之后不能弹出另一通道继续催促批准。

## 4. 状态呈现

| 模型状态 | 文案方向 | 操作 |
|---|---|---|
| PENDING | 等待人工确认，尚未执行 | 当前通道确认/拒绝/取消 |
| APPROVED | 已批准，执行前复核 | 禁止重复批准 |
| EXECUTING | 正在执行 | 不提供“安全撤销”承诺 |
| SUCCEEDED | 执行完成 | 展示数据库回执摘要 |
| FAILED | 执行失败，效果以说明为准 | 不自动重试 |
| UNKNOWN | 执行结果未知，请先核对数据库 | 显著提示禁止直接重试 |
| REJECTED / CANCELLED | 已拒绝/已取消 | 不执行，不重新批准 |
| EXPIRED / INVALIDATED | 已过期/请求已失效 | 新意图需重新申请 |

加载、空列表、服务不可达、会话失效和权限不足均独立展示。不能仅靠短暂 Toast 承载 UNKNOWN 或审批失败；关键状态保留在页面。

## 5. 视觉与可访问性（拟定）

采用简洁本地工具风格：中性背景、统一间距/圆角/字体 tokens，危险色仅用于风险和破坏动作；颜色不作为唯一状态信号。具体色值、主题支持为设计建议，未获逐项锁定，不强制移植参考项目组件库。

使用语义化控件、可见标签、清晰焦点和键盘导航；弹窗需焦点约束、关闭后焦点归位。图标按钮须有名称。尊重 reduced-motion；不以动画遮挡 SQL。

长连接名允许换行，SQL 使用等宽区域和局部滚动，不能以省略号隐藏唯一审批依据。窄屏按钮换行而不遮盖；200% 缩放仍可操作。主题若实现则逐一验证，不宣称当前已有暗色模式。
