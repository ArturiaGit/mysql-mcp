# 项目全局约束

> 状态：目标实现的安全规范，尚未实现。用户需求来源见[需求基线](./REQUIREMENTS.md)；具体防护方式属于拟采用设计。

## 1. 安全不变量

| 编号 | 必须满足的规则 |
|---|---|
| C01 | 数据库密码只从本地管理页面进入服务端；不得出现在聊天、模型参数、工具返回、URL、日志或 Git。 |
| C02 | 普通连接配置只保存凭据引用；优先 Windows 系统凭据存储，失败不得静默降级明文。 |
| C03 | 管理服务仅监听回环地址，但所有敏感接口仍认证；校验 Host、Origin、CSRF，不开放宽泛 CORS。 |
| C04 | 数据库操作明确连接和目标数据库；歧义先问，不使用跨请求共享的当前数据库状态。 |
| C05 | DBA 账号权限是数据库授权上限，不能自动创建账号、授权或使用其他账号绕过失败。 |
| C06 | 所有写入与结构变更必须绑定用户明确需求并逐次人工确认；普通插入和新建也不能豁免。 |
| C07 | AI 不能用工具参数中的 confirmed、工具注解、一次性允许或自然语言自我声明替代人工批准。 |
| C08 | 原生确认必须经过实际客户端验证；不可靠时使用本地人工审批。原生拒绝后不得改道网页继续求批准。 |
| C09 | 审批绑定准确 SQL、连接版本、数据库、客户端会话及一次性请求。修改任一执行要素必须重新确认。 |
| C10 | SQL 分类、允许范围和驱动禁多语句共同执行；不能只靠提示词、首词正则或解析成功保证安全。 |
| C11 | 写操作不自动重试；超时/断连可能为结果未知，不得宣称已回滚或恰好一次。 |
| C12 | 限制执行时间、返回规模和资源占用；错误、审计和普通日志不得泄露凭据或原始业务数据。 |

## 2. SQL 支持策略（拟定）

读取工具仅允许经过验证的 SELECT 子集；列库、列表和结构通过专门工具生成安全查询。写工具覆盖常见 INSERT、UPDATE、DELETE，以及 CREATE/ALTER/DROP 的库表子集、TRUNCATE TABLE。

首期默认拒绝：多语句脚本、用户控制的 USE/SET/事务、CALL、过程/函数/触发器管理、授权管理、服务器管理、文件读写、无法分类的语句、跨数据库语句。CREATE DATABASE 和 DROP DATABASE 的目标可以不作为连接默认库，必须与显式 database 一致。

必须识别 CTE、子查询、注释、字符串、标识符和方言差异。阻止读取通道中的 INTO OUTFILE/DUMPFILE、锁定读取、用户变量赋值和未允许函数；可执行注释默认拒绝。不要把所有函数视为无副作用。视图、既有触发器和外键可能扩大影响，审批提示不能声称只影响 SQL 文面对象；不能证明影响范围时拒绝或交由 DBA 处理。

MySQL 只读事务可作为读取的附加防线，不替代分类、函数限制或数据库授权。解析器不支持的语法用 SQL_NOT_ALLOWED 明确报告，不当成权限错误。新增语法必须同步策略测试、接口和支持矩阵。

## 3. 确认与信任边界

原生确认采用服务端发起的 MCP elicitation，须验证准确 SQL 可完整展示、接受/拒绝/取消行为和权限模式不自动批准。能力协商只说明协议支持，不能证明真人点击。每次能力或客户端版本变化需复验；无法保证时网页后备。

网页审批需要用户认证会话和 CSRF 防护；MCP 工具不得调用网页批准接口。内部桥接通道只接受匹配待处理原生请求的响应，不提供任意 request_id 加 confirmed 的通用批准入口。网页与原生只能有一个有效审批通道，切换通道需撤销旧挑战。

本方案信任用户控制的本机操作系统及客户端，不提供对同用户权限恶意进程或伪造人工响应客户端的强隔离。不得把这个局限隐藏为“绝对无法绕过”。读取结果可能离开本机进入所选模型服务，应在接入说明中告知；凭据本地保存不等于业务数据不出机器。

## 4. 执行与存储

- 同一请求通过原子状态迁移取得执行权；重复批准只返回现有状态，不再次派发 SQL。
- 服务重启不恢复执行待审批 SQL。执行中断的记录保留 UNKNOWN，不重新派发。
- 连接执行参数变化使待审批请求失效；执行中禁止编辑或删除该连接，避免错用新凭据。
- DDL 可隐式提交，非事务表不可依赖回滚；取消请求不等于 MySQL 已停止执行。
- 配置原子写入；配置与系统凭据无法构成同一事务时，采用先写新凭据、再提交引用、最后清理旧凭据的补偿流程。失败不覆盖有效旧配置。
- 精确 SQL 和结果按短期内存数据处理；审计持久化只保存必要目标、类型、指纹、状态与时间。日志不存 SQL、参数、结果或秘密。
- 远程 MySQL 的 TLS 和证书信任策略须明确，不能用关闭校验处理连接错误。

## 5. 拟默认值（尚未配置或验收）

| 配置项 | 拟值 | 验证要求 |
|---|---|---|
| execution_timeout_ms | 30000 | 超时能释放资源；写入不自动重试 |
| max_rows | 1000 | 超限标记截断，不能声称完整 |
| max_response_bytes | 1048576 | 按编码后的响应控制，单行超限也受控 |
| approval_ttl_ms | 300000 | 服务端判定过期，不信任页面倒计时 |

连接超时、连接池大小、并发队列上限、会话时长和审计保留期在实现阶段明确后集中登记，不能以无限制作为无配置的默认。限制读取结果不代表数据库只扫描这些行，执行预算需独立控制。

## 8. 完成证据红线

R16 的完成判断必须追溯唯一功能、需求、验收标准、实现/测试文件和被测输入摘要。重复 ID、未覆盖需求、越界路径、证据缺失/失效、测试失败/跳过/零测试必须拦截。不得用同一功能多个新名称规避重复检查。

禁止 AI 自述、手填 passed、路线图勾选或 PR 合并替代实际验收。所有必要实机/人工标准缺失时保持未完成。对独立外部证明尚无可靠认证器时拒绝完成升级，而不是降为相信本地 JSON。

## 9. 协作交接的安全边界

阶段为 planning → implementation → documentation_delivery；代码问题 documentation_delivery → rework → documentation_delivery；文档-only 为 planning → documentation_delivery。角色/阶段、任务路径、删除/重命名和版本快照须共同检查，受约束机器产物不能扩大职责。计划/标准/策略/授权改变后旧交接失效，必须重新交接重验。

本地 run 报告及校验后嵌入的 TAP 副本只是诊断，CI 独立重跑；无应用构建工程必须填 not_applicable 及原因，不声称 MySQL 编译通过。Git 交付使用 `GOV_ROLE=antigravity`，Hook 检查实际 staged/ref/msg 和完整候选；角色变量、共享账号及本机记录不能认证真实身份、证明用户已转交或强制抵御同机恶意改写。交接接受、PR 创建/合并均不替代人工验收或数据库逐次批准。

## 10. 测试与开发环境安全边界

依据需求 S10，当前项目所处开发环境的本地数据库内已填充开发专用假数据，可直接连接并自由操作。为避免无意义的过度设计与工程资源浪费，特此明确：
1. **开发环境免 Mock 准则**：在开发与本地测试环境中，允许且倡导直接连接包含假数据的开发 MySQL 实例执行真实 CRUD 与 DDL 验证，彻底废除开发维护 Mock Driver、FakeSocket 虚拟协议桩的要求。
2. **生产环境安全不变量不变**：无论未来连接何种环境，C01~C12 规定的密码保护、二次人工审批、只读工具硬拦截、无自动提权等安全约束依然是不可动摇的底线。开发环境的假数据自由读写绝不等于生产环境可以绕过审批。
3. **CI 环境轻量离线准则**：远端 GitHub Actions Runner 默认无外部数据库常驻，自动化流水线仅运行 TypeScript 类型检查与纯内存逻辑单测（如 SQL AST 语法策略、脱敏过滤器），保障 CI 100% 确定性离线通过。
