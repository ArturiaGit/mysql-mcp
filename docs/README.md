> 状态：设计基线；应用尚未实现。本文档库的创建不代表软件实施、数据库连接或写操作已经获得授权。

## 1. 项目目标

通过本地连接管理页面保存多个 MySQL 连接，让 AI 经 MCP 读取数据，并在用户明确要求、数据库账号具备权限且完成人工二次确认后执行写入或库表结构变更。连接与数据库选择分离；密码只在本地页面输入。

## 3. 状态与规范力度

| 标签 | 含义 |
|---|---|
| 用户已确认 | 用户明确选择的需求或范围 |
| 已验证事实 | 有检查或资料依据，并限定证据适用范围 |
| 拟采用方案 | 设计建议；尚未安装、实现或验证，不冒充用户逐项确认 |
| 待确认 | 需要用户或 DBA 决策 |
| 待验证 | 有验证方法，但尚无通过证据 |

“必须”表示目标实现应满足的规则，不表示已经实现；“建议”表示推荐但可论证调整；“可选”表示非首期必要项。批准编写文档不等于批准全部依赖选择、程序开发、修改客户端配置或执行数据库操作。

代码拟位于工作区 `mysql-mcp/` 子目录；本规范位于工作区 `docs/`。文中的未来代码路径、npm 脚本、UI 路由均为规划，不是当前存在的文件或命令。
